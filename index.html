Problem

Make university profile data and campus facilities browsable while providing an admin interface to update the same information.

My contribution

I implemented the public and admin React interfaces, CRUD forms, Supabase data and authentication services, PostgreSQL setup, and building/room endpoints for the campus-map integration.

Decisions

The React application uses the Supabase SDK directly. Database policies allow public reads and authenticated writes for profile tables. A separate API supplies building and room data to Unity; it is not the route for the dashboard’s CRUD operations. Route-level lazy loading separates the public, login, and admin screens.

Testing evidence

The repository contains tests for required fields in building, facility, and program forms, plus API response tests with mocked database queries.

Problem

Connect a browser control panel to sensor readings and device commands, with a repeatable way to demonstrate the system without physical hardware.

My contribution

I implemented the HTML/CSS/JavaScript dashboard, API gateway, separate Express services, MySQL models, MQTT message handlers, and device integration for this PPLBS course project.

Decisions

The dashboard polls the HTTP API every five seconds. The gateway routes requests to services for authentication, climate, devices, sensors, alerts, control, and security. MQTT carries sensor messages and device commands; Docker Compose starts the backend services and MySQL.

Verification path

The repository’s Node.js simulator publishes the same MQTT topics used by the ESP32 implementation. Its scripted scenarios include motion, a gas spike, a fire alert, and recovery. Run it with the dashboard to inspect telemetry and send light, fan, and lock commands.
